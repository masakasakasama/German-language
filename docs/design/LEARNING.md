# 学習・復習ロジック仕様

## 流用元と原則

主な流用元は `Language_learning` の `js/srs.js` / `js/storage.js` / `js/views.js`。調査したcommitは `c3daaac51a803dd9c74e3fd21011260219486269`。オリジナルSRSを `reference/legacy-srs.js` に保存した。これを製品にWebViewとして埋め込むのではなく、Kotlinの純粋関数へ移植する。

CPRE/CAPMは正誤×自信の別スケジューラ。混ぜない。Anki/FSRSという名前だけを根拠に新しいアルゴリズムへ置換しない。既存実装は独自の段階間隔であり、現行Ankiの全仕様と同一ではない。

## 状態と自己評価

初期SRS: ease=2.5、intervalDays=0、reps=0、lapses=0、last=null。カード未学習の場合はSRS行を作らず「未学習」として扱う。紹介後に作成する。

| 入力 | 更新 |
|---|---|
| dontknow / わからない | ease=max(1.3,ease−0.2)、interval=1、repsを維持、lapses+1、翌日復習 |
| ok / 少しわかる | 下記goodを1回適用 |
| know / わかる | interval=max(7,JS_round((intervalまたは1)×2))、ease=min(3.0,ease+0.15)、reps+1、lapses維持 |
| 客観正解 good | reps<4なら[1,3,7,14][reps]、以降はJS_round(interval×ease)、reps+1、ease/lapses維持 |
| 客観誤答 again | interval=0、ease=max(1.3,ease−0.2)、lapses+1、reps=0、当日復習 |

JS_roundは非負数に対してfloor(x+0.5)。Kotlinの銀行丸めで差を生じさせない。`know`は`review(easy)`とは別の処理。`hard`/`easy`は既存内部gradeとして参照関数にあるが、v1製品の入力には公開しない。ランダムfuzzは既存review/applyMarkから呼ばれておらず、v1でも適用しない。

期限は当日の端末ローカル日付にinterval日を足す。実装はClock/ZoneIdを注入し、`dueLocalDate`と計算時zoneを保存する。due<=todayなら期限対象。日時の差を24時間で割って日付を決めない。夏時間はLocalDateで扱う。元JSの期限ISOはその計算zoneで解釈し、保存日付に変換する。端末zone変更時は保存されたdueLocalDateの暦日を新zoneの今日と比較し、履歴・XPの当時の日付は書き換えない。

次回日数が端末日付の限界を超える不正入力は検証で拒否する。正常状態のinterval/reps/lapsesは非負、easeは1.3..3.0。

## 移植時に修正する既存の問題

1. **二重更新:** 既存introはsetMark→handleAnswer(true)でapplyMark後にgoodも適用する。v1ではINTRO_ASSESSMENTを1イベントにし、applyMarkだけを1回適用する。紹介を客観正解に数えない。
2. **評価変更による水増し:** 押し直しは保存前の状態から同じeventIdを再計算して置換する。SRS/報酬を累積更新しない。次へ移動後の再評価は別イベントだが、同日報酬は重複させない。
3. **苦手抽出から誤答カードが消える:** 元のweakCardIdsはreps==0を除外するため、againでreps=0になった忘却カードを落とす。v1は「回答履歴がある」カードを対象にし、reps=0でも除外しない。未回答カードは対象外。
4. **dontknowのコメント:** resetと書かれたコメントと異なり実装はrepsを維持する。v1も維持し、勝手にリセットへ変更しない。
5. **初回hardの過剰な期限混同:** 自己評価dontknowは翌日、客観誤答againは当日。画面と説明で区別する。

修正以外の代表入力は参照JSONに合わせる。修正ケースの差は意図した変更としてテストする。

## 出題キュー

期限復習は学習済み＋期限到来のカードのみ。順番はdueLocalDate昇順→weakness降順→cardId昇順。同じ日付に大量のカードがある場合も上限5/10/20で分割する。未学習カードを期限件数に含めない。

苦手スコアは既存式を維持: lapses×3 + max(0,2.5−ease)×4 + (interval<=1かつreps>0なら2) + min(超過日数,7)×0.5。3以上を苦手対象とし、スコア降順→cardId昇順。対象は前述の「回答履歴がある」カードに修正する。

新規レッスンは教材指定の3フレーズを順番に紹介し、続けて3フレーズの練習。1フレーズ紹介で1イベント、別の練習問題で1イベント。既存二重更新の修正とは、別の問題に答えることを止める意味ではない。

紹介時にdontknow、または客観誤答のカードは再練習を追加する。別カードを2枚挟むかセッション末尾へ置く。追加は各カード最大2回、全体最大6問。連続誤答で無限ループにしない。上限後は解説確認で終了でき、当日/翌日の復習予定は残る。進捗は「本編x/6」「追加復習x/y」を分け、分母が突然増えて進捗が戻らない。

復習は基本フラッシュカード→自己評価。苦手集中も同じ。利用者が「問題で練習」を選んだ場合だけ客観問題にする。収集詳細の「復習する」は期限を問わず1枚の自己評価セッションを開始できる。

## 客観採点

| 形式 | 判定 |
|---|---|
| 選択 | optionId完全一致。選択肢は意味・品詞・難易度が近いもの |
| 聞き取り | 手本を再生し、選択または短文入力。訳は回答後に表示 |
| 穴埋め | 教材に明記した許容語形へ一致 |
| 並べ替え | tokenId列の許容系列へ一致。複数語順が可能なら別解登録 |
| 短文入力 | 問題のnormalizationポリシー＋許容解答の比較 |

基本正規化はUnicode NFC、前後空白除去、連続空白の圧縮、末尾の .!? の除去。内部の単語・語順・冠詞は変更しない。自由な同義文を勝手に正解にしない。

phraseモードではcasefold比較し、原文と異なる名詞大文字は注意だけ表示。orthographyモードでは大文字小文字を厳密に判定。ä/ö/üをa/o/uへ潰さない。ae/oe/ue、ss↔ßの代替は教材allowedAnswersに明示された場合だけ許可する。補助キーä ö ü ßを入力欄上に設ける。句読点を学ぶ問題は別ポリシーで厳密判定。

ヒント付き正解はSRSではgoodだが、正答率統計では「ヒントあり」を分ける。正答率は客観問題の初回・ヒントなし回答だけで計算し、自己評価を正解に混ぜない。該当回答0件は「—」。

## 会話・音声

4場面×3会話。各会話は相手発話→学習者発話→相手応答の固定3ターン。相手の音声再生後にユーザーの回答を待つ。任意録音はAndroid SpeechRecognizerのde-DE、利用可能ならon-deviceを優先。非対応・オフライン不可なら文字回答に切り替える。

認識結果は編集/確定を経て短文入力と同じ採点へ渡す。自動送信しない。認識失敗は客観誤答にせず、記録を更新しない。「発音点数」は出さない。会話内の「練習を終える」自己評価は各カード1回だけ適用し、採点済みの客観回答には重ねない。繰り返し聞く/話すだけの操作はSRS更新なし。

音声は同梱教材音声がある場合はそれを優先、それ以外は端末TTS。ドイツ語voiceの利用可否を検出し、通常0.9倍/低速0.7倍、標準速度は設定で0.7/0.9/1.0。TTSデータ未導入の場合はOSの導入画面へ任意誘導。音声が使えなくても本文のレッスンを完了できる。v1の完全なオフライン音声保証は同梱音声を制作した対象に限る。
